# Task 4: Orchestrate and resume runs

**Depends on:** [Task 1](01-assess-fit-and-select-data.md), [Task 2](02-run-isolated-pi-sessions.md), [Task 3](03-bridge-scoring-and-costs.md)

**Goal:** Provide a guarded pilot/full CLI that writes case-level reports and resumes without rerunning valid completed work.

**Files:**

- Create: `scripts/longmemeval-v2.ts`
- Create: `scripts/longmemeval-v2/run.ts`
- Create: `test/longmemeval-v2-run.test.ts`

**Reuses:** `loadDataset(root: string): Promise<BenchmarkDataset>`, `selectCases(dataset: BenchmarkDataset, set: 'pilot' | 'full', pilotIds: readonly string[]): QuestionCase[]`, and `renderTrajectory(trajectory: Trajectory): string[]` in `scripts/longmemeval-v2/dataset.ts`; `runPiSession(input: PiSessionInput): Promise<PiSessionResult>` and `UsageTotals` in `scripts/longmemeval-v2/pi.ts`; `estimateCost` and `estimatePreflight` in `scripts/longmemeval-v2/cost.ts`; `score_case` in `scripts/longmemeval-v2/score.py`. `scripts/two-session-demo.ts` demonstrates separate session files and a unique Git fixture but must not be changed.

**Precondition:** The external upstream checkout and data snapshot match `2cc8c540bdb87fe6761629b585e727e1c4704520` and `f152293e235517d504809563c833d7190b8c713b`. Task 1's `scripts/longmemeval-v2/pilot.json` exists. The selected `openai-codex` model must be authenticated for paid execution. If chosen cases need LLM grading, check `OPENAI_API_KEY` before ingestion; never print it. The operator must approve paid execution separately from this plan.

**Site conditions:** Small-tier questions in each domain share one ordered 100-trajectory haystack. The runner may ingest it once per domain into one unique Git fixture, using a new Pi session per bounded history chunk; all later query sessions must use new session files in that same fixture. For the plugin-off control, start new Pi question sessions without the extension or history; distinguish its lower cost. Do not put the dataset, gold answers, upstream checkout, or report files inside the Pi fixture. Model-directed record selection and the default 10 MiB quota can cause incomplete coverage or quota errors; stop and mark a run incomplete rather than treating failed ingestion as success. For comparison, require the same question text, exact configured model ID, thinking level, and eligible case IDs in both modes. Benchmarks are adapted, non-official, and not 451-case scores when image cases are excluded. Runs can retain sensitive trajectory text in private session/JSONL logs; keep output folders outside Git and set directory permissions to 0700.

## Steps

1. Define `RunOptions` in `run.ts` with `dataRoot`, `upstreamRoot`, `set: 'pilot' | 'full'`, `model`, `thinking`, `outputRoot`, `ratesPath?`, `execute`, and `resumeDir?`; export `runBenchmark(options: RunOptions): Promise<RunReport>`. In the `scripts/longmemeval-v2.ts` entry point, parse matching flags: `--data-root`, `--upstream-root`, `--set`, `--model`, `--thinking`, `--output-root`, optional `--rates-json`, optional `--resume`, and `--execute`. Reject unknown flags, unsupported models, missing pinned files, duplicate IDs, and changed hashes.
2. Before any Pi or grader process starts, check upstream/data revisions, pilot hashes, file integrity, model visibility, grader-key presence for semantic cases, planned history-chunk and question counts, and project quota assumptions. Require at least 1 GiB available in the output filesystem for paid work; warn during preflight when it is missing. Compute a plugin fingerprint from sorted paths and file contents under `src/`, `vendor/`, and `skills/pi-context/`, plus `package.json`, `package-lock.json`, and `tsconfig.json`; include a Git HEAD only when it exists. Compute a separate fingerprint for `scripts/longmemeval-v2*`. Print eligible/excluded counts, rough calls/tokens, separate ingestion and control costs, and estimated or unknown USD. Without `--execute`, report missing auth or storage as warnings and exit without starting a model or judge. With `--execute`, fail before ingestion if semantic judging lacks a key or output storage is insufficient. On resume, require `--execute` again.
3. For paid work, make a unique run directory with 0700 permissions and a distinct empty Git repository per domain. Stream selected trajectory IDs in order to Pi memory sessions using `renderTrajectory`, then checkpoint each successfully settled history chunk. Do not send question/answer/evaluator fields during ingestion. Run one fresh plugin-on and one fresh plugin-off question session per selected case with the same pinned model/thinking; ask for a final `\\boxed{answer}` and allow `\\boxed{UNKNOWN}`. Score both answers through the Python bridge, keeping gold and evaluator specs out of Pi processes. Record category/domain accuracy, token counts, ingestion cost, answer cost, judge-call count, USD estimates or unknown states, actual provider/model identity, dataset and the plugin Git revision when available or an explicit source fingerprint, project ID, excluded IDs/counts, and method limits.
4. Write `checkpoint.json` atomically after every completed chunk, answer, and grade; use 0600 files and a temp-file rename. Save each session log under a deterministic stage/case/mode name. On resume, reject changed dataset hashes, pilot IDs, model/thinking, plugin fingerprint, runner fingerprint, tier, or rate assumptions; do not require a Git HEAD. Recover a completed settled log after a crash before checkpoint update; do not replay a potentially committed `record` call when a log is incomplete or ambiguous. Resume only missing or invalid stages. Exit nonzero and mark `status: incomplete` on data/auth/model/grade failure; never emit complete aggregate scores until every eligible paired case is scored. Keep incurred token and cost information on failed runs.
5. Test a synthetic two-domain run with a fake Pi executable and fake grader, including no-execute, correct 0700/0600 permissions, extension toggling, ordering, paired cases, excluded images, model mismatch, missing judge key, absent Git HEAD, quota failure, malformed JSONL, interruption, stale resume hashes, and a settled log recovered after checkpoint interruption. Tests must not call a real provider.

- [ ] A failed run has `status: incomplete` and an unambiguous checkpoint; a same-input resume skips completed valid stages and requires `--execute`.
